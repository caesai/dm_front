## Депозитная функциональность

### Даты с депозитом

Даты с атрибутом `requires_deposit` требуют предоплаты депозита.

**Структура IAvailableDay:**

```typescript
{
  date: '2025-08-24',
  attributes: ['requires_deposit'],
  deposit_per_person: 1500
}
```

**Логика:**

1. При выборе даты с депозитом показывается `DepositInfoModal`
2. Пользователь подтверждает условия нажатием "ОК"
3. Фильтруются способы подтверждения — только "По телефону" и "В Telegram"

### Отмена депозитного бронирования

При отмене бронирования с депозитом:

1. Показывается `DepositCancelModal` с условиями возврата
2. Пользователь выбирает "Нет, оставить" или "Всё равно отменить"
3. При подтверждении открывается стандартный `CancelBookingPopup`

**Условия возврата:**

- За 3+ дня — 100%
- Менее чем за 3 дня — 50%
- В день брони — без возврата

## Запуск тестов

```bash
# Все тесты бронирования
npm test -- --testPathPattern="booking|useBookingForm"

# Только useBookingForm
npm test -- --testPathPattern="useBookingForm"

# Только страницы бронирования
npm test -- --testPathPattern="booking/"

# С покрытием
npm test -- --testPathPattern="booking" --coverage
```

## Согласованность страниц

Все три страницы бронирования используют:

- Хук `useBookingForm` для управления состоянием
- Одинаковую структуру формы
- Одинаковые компоненты (BookingContactsBlock, ConfirmationSelect и др.)
- Одинаковую логику валидации
- Одинаковую фильтрацию способов подтверждения для депозитных дат

**Различия:**

| Страница              | Ресторан   | Дата        | Event ID | Навигация после  |
| --------------------- | ---------- | ----------- | -------- | ---------------- |
| BookingPage           | Выбирается | Выбирается  | null     | /myBookings/{id} |
| RestaurantBookingPage | Фиксирован | Выбирается  | null     | /myBookings/{id} |
| EventBookingPage      | Из события | Фиксирована | event.id | /tickets/{id}    |
